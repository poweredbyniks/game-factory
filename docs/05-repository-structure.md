# E. Repository structure

One monorepo, npm workspaces. Code lives only under `engine/` and `tools/` (and `server/` from Phase 2).
Everything else is data that the tools validate and compile.

```
game-factory/
├── README.md                  quick start and command reference
├── CLAUDE.md                  working rules for AI agents in this repo
├── package.json               workspaces + root scripts (check, test, gf, dev, e2e, build:ios|android|all)
├── tsconfig.base.json
├── vitest.config.ts
│
├── engine/                    ALL shared runtime code
│   ├── schemas/               @gf/schemas: zod schemas, inferred types, migrations, backend API contracts
│   ├── core/                  @gf/core: headless runtime (no React, no assets)
│   │   └── src/  rng · events · clock · inventory · energy · economy · progression · story
│   │             · store · purchases (two-phase) · ads-policy · analytics · remote-config · experiments
│   │             · save (+ purchase ledger) · attempt outbox · level-session · runtime
│   │             · verify (server-side attempt replay) · providers (platform interfaces + mocks)
│   ├── mechanics/
│   │   ├── associations/      @gf/mechanic-associations: rules · solver · generator · bot
│   │   └── tripeaks/          @gf/mechanic-tripeaks: rules · layouts · solver · generator · bot
│   └── app/                   @gf/app: the Expo shell, the only React Native code
│       ├── app.config.ts      native identity per game, from data only
│       ├── eas.json           build profiles: development · staging · production
│       └── src/  theme runtime · screens · board views (one per mechanic) · popups
│                 · platform/ (the platform layer: per-environment services, capabilities.json, back handling)
│                 · generated/ (compiled bundle, release config, asset registry; gitignored)
│
├── tools/                     @gf/tools: the `gf` CLI
│   └── src/  compile · validate · levels · simulate · create-game · build · schemas · art/ (icon rasterizer)
│             · server-engine/ (the engine as one GraalJS script for the Java backend) · golden (attempt fixtures)
│
├── templates/                 game templates (data)
│   └── solitaire_adventure/
│       ├── template.json      core loop, mechanics, module defaults, required icons, sounds and files
│       └── defaults/          economy · store · progression · leaderboards · levelgen per mechanic · strings
│
├── themes/                    reusable visual identities (data + assets)
│   ├── cozy_village/          theme.json · assets/*.svg · fonts/*.ttf (+ OFL license) · sfx/
│   └── tropical_resort/
│
├── content/                   reusable content libraries
│   └── word-packs/en/core_en.json
│
├── games/                     ONE SMALL DATA PACKAGE PER GAME
│   └── maplebrook/
│       ├── game.json          identity, template, theme, mechanic, modules (schemaVersion 2)
│       ├── release.json       store identity, EAS project, endpoints, ad unit ids, SKU pattern
│       ├── store/en.json      store listing per locale
│       ├── assets/            icon, adaptive icon, monochrome icon, splash, favicon
│       ├── progression.json   chapters, unlocks, chapter rewards, story hooks
│       ├── levelgen.json      difficulty curve for the generator
│       ├── levels.json        generated by `gf levels generate`, committed
│       ├── characters.json    cast
│       ├── story.json         dialogue beats
│       ├── economy.json, store.json, monetization.json, leaderboards.json   optional overrides
│       └── localization/en.json   game-specific strings (names, story, store titles)
│
├── deploy/                    store-specific policy shared by every game
│   ├── ios/defaults.json      id prefix, iPad support, export compliance, App Store categories
│   └── android/defaults.json  id prefix, blocked permissions, Play category, default track
├── localization/              engine UI strings shared by every game (en.json, ...)
├── analytics/                 event taxonomy (events.json)
├── monetization/              shared monetization defaults (defaults.json)
├── config/remote/             remote-config payloads per game (served over HTTPS per environment)
├── tests/                     cross-package tests: content validity, golden playthroughs, attempt verification, e2e
├── build/                     generated output only (bundles, reports, screenshots, web builds); gitignored
└── schemas/                   generated JSON Schema files for editors, AI and the backend API
```

Planned, not created yet: `server/` (Java Spring Boot backend as a Maven project, Phase 2, see
[L](12-backend.md)), `ai/` (prompt templates and
generators, Phase 3), `engine/app/src/fx` (shared game-feel module, Phase 2), `engine/app/modules/` and
`engine/app/plugins/` (only if native code is ever needed). The compiler resolves `@shared/…` theme
asset paths to `assets/shared/`, which no theme uses yet.

## Requirement folders mapped

| Requirement | Here |
|---|---|
| `/engine` `/templates` `/games` `/themes` `/content` `/tools` `/config` `/localization` `/analytics` `/monetization` `/tests` `/docs` | same names |
| `/assets` | per theme (`themes/ID/assets`) and per game (`games/ID/assets`); `assets/shared/` when shared art appears |
| `/ai` | Phase 3 |
| `/platform` | `engine/app/src/platform/` ([F §7](06-ios-android-architecture.md)) |
| `/ios`, `/android` | generated by `expo prebuild` per game, never committed |
| `/deploy/ios`, `/deploy/android` | `deploy/ios/`, `deploy/android/` |
| `/build` | `build/` (generated); build configuration is `engine/app/eas.json` plus `gf build` |

## What a game package contains

A game is about a dozen JSON files, its icons and optional overrides. It never contains code. Measured
on the two Phase 1 games:

| Game | JSON files | Authored JSON | Generated `levels.json` |
|---|---|---|---|
| `maplebrook` (story, cast, custom tutorials) | 9 | 669 lines | 1,618 lines |
| `palm_peaks` (made with `create-game`, story off) | 10 | 258 lines | 2,318 lines |

| File | Required | Written by |
|---|---|---|
| `game.json` | yes | `create-game`, then a designer |
| `release.json` | yes | `create-game` (`--ios-id`, `--android-id`), then release setup |
| `store/LOCALE.json` | for release | `create-game` stub, then a writer or AI |
| `assets/*.png` | yes | `gf assets icons` placeholders, then final art |
| `progression.json` | yes | `create-game`, designer or AI |
| `levelgen.json` | yes | `create-game` from the template curve |
| `levels.json` | yes | `gf levels generate` (committed, reviewable) |
| `characters.json`, `story.json` | if `story` is enabled | designer or AI (Phase 3) |
| `economy.json`, `store.json`, `monetization.json`, `leaderboards.json` | no | designer, overrides template defaults |
| `localization/LOCALE.json` | yes | designer or AI, validated for coverage |

## Merge order at compile time

```
monetization/defaults.json, localization/LOCALE.json      shared defaults
  < templates/T/defaults/*                                template defaults
  < themes/THEME/theme.json                               visual identity
  < games/ID/*.json                                       game files
  < games/ID/game.json "overrides"                        last-mile tweaks

deploy/PLATFORM/defaults.json < games/ID/release.json     release configuration (outside the bundle)
```

Objects deep-merge. Arrays replace. The result is validated as a whole.

## Generated artifacts

| Artifact | Produced by | Committed |
|---|---|---|
| `games/ID/levels.json` | `gf levels generate` | yes: it is content and must be reviewable |
| `games/ID/assets/*.png` placeholders | `gf assets icons`, `create-game` | yes, until replaced by final art |
| `engine/app/src/generated/*` | `gf compile ID --app` (also on EAS build workers) | no |
| `build/bundles/ID/bundle.json` | `gf compile ID` | no |
| `build/reports/*` | `gf simulate`, `gf levels analyze` | no |
| `schemas/*.schema.json` | `gf schemas export` | yes: editors and the Java backend's contract tests reference them |
| `build/server-engine/` (`gf-engine.js`, manifest, shipped bundles, contract fixtures) | `gf server-engine` | no: CI builds it before the Java build |
